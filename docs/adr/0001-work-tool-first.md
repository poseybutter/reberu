# ADR-0001. 업무 툴 우선과 공간 계층

> 버전: v0.1.0\
> 수정일: 2026-11-04

- 상태: Accepted
- 영향: [product/overview.md](../product/overview.md) §4, [product/spaces.md](../product/spaces.md), [product/screens.md](../product/screens.md) B0·C0

## 맥락

- reberu는 "가상 사무실 + 힐링" 콘셉트를 가진 팀 업무 관리 서비스다.
- 메타버스형 서비스는 공간이 화면의 주인이 되기 쉽다. 업무 정보가 공간 뒤로 밀리면 업무 툴로서 쓸모가 떨어진다.
- 바닷가 요가원 같은 차분한 분위기를 원하지만, 3D를 과하게 내세우면 업무 집중을 해친다.

## 결정

- 업무 관리가 본체이고, 공간은 그 위에 얹는 선택 계층이다. 둘이 부딪히면 업무 쪽을 고른다.
- 업무 행동(업무, 할 일, 현재 상태, 알림)은 공간을 거치지 않고 어디서나 한다.
- 공간 화면은 **공간 뷰 + 업무 패널** 두 영역으로 나누고, 업무 패널은 모든 공간에서 같은 자리·같은 구성이다.
- 업무·프로젝트·리포트·관리 화면(C, D, E, F)은 공간 없는 2D 화면이다. 공간은 B 화면에만 있다.
- 공간마다 연출 세기를 다르게 한다. 힐링 존 강, 로비·라운지·조직 공간 중, 내 자리·회의실 약, 업무·관리 화면 없음.
- 연출은 업무를 가리지 않는다. 레벨업·업적은 짧은 알림을 먼저 띄우고, 눌렀을 때만 자세히 연다.
- 소리는 기본 꺼짐, 깜빡임·번쩍임 효과는 쓰지 않는다.
- 단순하게 보기(B7)에서도 모든 기능을 쓴다. 공간에서만 되는 업무 기능은 만들지 않는다.

## 검토한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 공간이 첫 화면이고 업무는 공간 안의 사물(책상 등)을 눌러 연다 | 업무를 하려면 공간을 이동해야 한다. 업무 툴로서 동선이 길어진다 |
| 공간과 업무를 완전히 다른 앱처럼 나눈다 | 공간에 있는 동안 업무 상황을 볼 수 없어 공간을 열어 두지 않게 된다 |
| 모든 화면에 같은 세기의 3D | 업무·관리 화면에서 정보 밀도가 떨어지고 기기 부담이 크다 |

## 결과

- 좋아지는 점: 공간을 끄거나 3D를 못 그리는 기기에서도 업무가 그대로 된다. 공간 모듈을 독립적으로 만들 수 있다.
- 감수하는 점: 공간 화면은 업무 패널 몫만큼 공간 뷰가 좁다. "내 자리" 공간의 역할이 업무 패널과 겹친다(OQ-03).
- 후속 작업: 업무 패널의 정보 구성을 [product/screens.md](../product/screens.md) B0에 고정한다. 글을 쓰는 동안 이동 키를 막는 규칙을 [product/spaces.md](../product/spaces.md)에 둔다.
