# ADR-0017. 관측: Prometheus 지표와 Grafana 대시보드

> 버전: v0.1.0\
> 수정일: 2026-11-05

- 상태: Accepted
- 영향: [operations/observability.md](../operations/observability.md), [docs/ai/backend.md](../ai/backend.md) §1, OPS-OBS-01~10

## 맥락

- 배포한 서버가 느려지거나 오류가 늘어도 지금은 알 방법이 로그뿐이다.
- 이벤트 전달이 밀리거나(ARCH-EVT-04) 로그인 실패가 급증하는 일은 숫자로 봐야 빨리 알 수 있다.
- 복사해 쓰는 단체도 같은 방법으로 운영할 수 있어야 하고, 관측 도구가 없어도 앱은 돌아야 한다.
- 프로젝트에는 Spring Boot Actuator가 이미 있다.

## 결정

- 앱은 Micrometer로 지표를 만들고 Prometheus 형식으로 내보낸다.
- Prometheus가 지표를 모으고, Grafana가 대시보드와 경보를 맡는다.
- 두 도구는 Docker Compose의 선택 프로필로 띄운다. 띄우지 않아도 앱은 그대로 돈다.
- 대시보드와 경보 정의는 파일로 저장소에 둔다.
- 로그는 새 도구 없이 표준 출력에 구조화된 형식으로 쓴다. 분산 추적은 지금 두지 않는다.

## 검토한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 로그만 쓴다 | 응답 시간, 오류 비율, 밀린 이벤트 같은 추세를 보기 어렵다 |
| 상용 관측 서비스 | 비용이 들고, 복사해 쓰는 단체마다 계약해야 한다 |
| 로그 모음·추적까지 포함한 전체 관측 스택 | 서버 한 대 규모에서 운영할 구성 요소가 너무 많다. 필요해지면 더한다 |

## 결과

- 좋아지는 점: 오류, 지연, 이벤트 밀림, 보안 이상 징후를 대시보드와 경보로 본다. 업계에서 흔한 구성이라 복사한 단체도 익숙하게 쓴다.
- 감수하는 점: 지표 끝점을 외부에 열지 않도록 지켜야 한다(OPS-OBS-01). 지표 이름표에 개인정보가 들어가지 않게 지켜야 한다(OPS-OBS-03).
- 후속 작업: 의존성(Micrometer Prometheus) 추가와 Compose 이미지 판은 구현 시작 때 따로 승인을 받는다.
