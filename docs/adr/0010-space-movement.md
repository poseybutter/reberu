# ADR-0010. 공간 이동: 공간 사이 선택, 공간 안 보행, 위치 비영속

> 버전: v0.1.0\
> 수정일: 2026-11-04

- 상태: Accepted
- 영향: [product/spaces.md](../product/spaces.md), [architecture/realtime.md](../architecture/realtime.md) 위치 절

## 맥락

- 공간 안에서 사람이 어떻게 움직일지 정해야 했다.
- 처음 안은 "구역 + 자리"였다. 구역을 고르면 빈 자리에 앉고, 서버는 구역과 자리 번호만 주고받는다. 좌표를 실시간으로 보내지 않아 가볍다.
- 일반적인 3D 공간 데모는 키보드·조이스틱 보행, 3인칭 추적 카메라, 충돌 처리, 위치 실시간 동기화로 만든다.
- 바닷가·회의실 같은 공간에서는 걸어 다닐 수 있어야 한다는 요구가 나왔다. 반면 업무·프로젝트 관리는 공간이 아니다.

## 결정

- **공간 사이**는 공간 목록이나 미니맵에서 골라 바로 옮긴다. 공간에서 공간으로 걸어가지 않는다.
- **공간 안**은 걷는다. PC는 WASD·방향키·클릭, 휴대폰은 화면 왼쪽 아래 조이스틱.
- 공간마다 경계가 있고 큰 물체는 통과하지 못한다. 자리·소품 가까이 가면 행동 버튼("앉기", "차 마시기" 등)이 뜬다.
- 공간마다 정원이 있다. 정원이 차도 업무 패널과 업무 화면은 그대로 쓴다.
- 카메라는 캐릭터 뒤에서 천천히 따라오고 크게 돌지 않는다.
- 글을 쓰는 동안(업무 패널, 채팅 입력)에는 이동 키가 먹지 않는다. 공간 뷰를 누른 뒤에만 이동한다.
- 위치는 같은 공간 안에서만 주고받고 서버 메모리에만 둔다. DB에 쓰지 않는다.
- 산길처럼 정해진 길을 자동으로 걸을 때는 좌표 대신 구간과 진행 정도만 보낸다.

## 검토한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 구역 + 자리(보행 없음) | 공간 안에서 걸어 다니는 경험이 없어 공간의 의미가 약하다 |
| 모든 공간을 하나의 맵으로 이어 걷기 | 업무 중 이동이 일이 된다. 공간 사이는 고르는 편이 빠르다 |
| 위치를 저장해 다음 접속 때 복원 | 쓸모에 비해 쓰기 부하가 크다 |
| 업무 화면에도 보행 | 업무 툴 우선 원칙([ADR-0001](0001-work-tool-first.md))에 어긋난다 |

## 결과

- 좋아지는 점: 공간 안에서는 걷는 재미가 있고, 공간 사이와 업무는 빠르다. 위치 저장 부하가 없다.
- 감수하는 점: 위치 실시간 동기화가 필요하다. 많은 사람이 모이는 공간은 부하 제어가 필요하다([architecture/realtime.md](../architecture/realtime.md)).
- 후속 작업: 위치 빈도 상한, 가까운 사람 위주 전송, 경계 밖 좌표 버리기를 요구사항으로 둔다.
