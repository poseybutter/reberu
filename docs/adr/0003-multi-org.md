# ADR-0003. 멀티 조직 구조와 배포 모드

> 버전: v0.1.0\
> 수정일: 2026-11-04

- 상태: Accepted
- 영향: [architecture/tenancy.md](../architecture/tenancy.md) 배포 모드·구조 절, [architecture/security.md](../architecture/security.md), [product/overview.md](../product/overview.md) §6

## 맥락

- 처음에는 "배포 1개 = 조직 1개"로 정했다. 단체가 저장소를 복사해 자기 서버에 띄우는 모델과 맞았다.
- 이후 두 요구가 생겼다.
  - 바깥 사람이 직접 조직을 만들고 사람을 추가할 수 있어야 한다.
  - reberu는 특정 단체만이 아니라 누구나 쓰는 서비스(대민용)가 주된 목적이다.
- 한 서버에 여러 조직이 있으면 조직 사이 격리 층이 하나 더 필요하다.

## 결정

- 처음부터 **한 배포에 조직 여러 개를 담는 구조**로 만든다. 조직 아래에 팀 여러 개가 있다.
- 배포 설정으로 모드를 고른다.
  - `MULTI_ORG`(조직 만들기 모드, 기본): 로그인한 누구나 조직을 만들고 첫 조직 관리자가 된다.
  - `SINGLE_ORG`(조직 하나 모드): 조직이 하나뿐이다. 첫 조직 관리자와 조직 이름을 환경 변수로 정한다.
- 두 모드는 같은 코드·같은 구조다. 모드는 조직을 만들 수 있는지와 조직 찾기를 보일지만 바꾼다.
- 두 모드 모두 v0.1에 넣는다.
- 계정은 배포 전체에 하나다. 계정과 조직 사이에 조직 멤버십을, 계정과 팀 사이에 팀 멤버십을 둔다.
- 조직과 팀의 데이터는 완전히 분리한다. 요청마다 조직 멤버십 → 팀 소속 조직 → 팀 멤버십 순서로 확인한다([ADR-0006](0006-tenant-isolation.md)).
- 여러 팀이 함께하는 일은 조직 소속 데이터(조직 공간 모듈)로만 한다.

## 검토한 대안

| 안 | 내용 | 버린 이유 |
| --- | --- | --- |
| 가. 배포 1개 = 조직 1개 | 바깥 사람은 손님으로만 들어오고, 자기 조직이 필요하면 직접 배포한다 | 누구나 쓰는 서비스가 될 수 없다. 써 보려는 사람이 서버를 띄워야 한다 |
| 나. 여러 조직만(SaaS) | 누구나 조직을 만든다 | 한 단체만 쓰는 배포에도 조직 만들기·찾기가 열려 불필요한 공격면이 생긴다 |
| **다. 여러 조직 구조 + 배포 모드** | 구조는 여러 조직, 모드로 조직 하나를 고를 수 있다 | 채택 |

- 처음에는 조직 만들기 모드를 v0.3 이후로 미뤘다. 누구나 쓰는 서비스가 주된 목적임을 확인하고 v0.1로 당겼다.

## 결과

- 좋아지는 점: 공개 서비스와 단체 배포를 같은 코드로 운영한다. 격리 규칙을 처음부터 조직·팀 두 층으로 테스트한다.
- 감수하는 점: 모든 팀 데이터 접근에서 조직 확인이 한 번 더 든다. 조직 남용(가짜 조직, 초대 남발)을 막는 장치가 필요하다(OQ-26, OQ-27). 조직 하나 모드에서도 조직 격리 테스트를 늘 돌린다.
- 후속 작업: 조직 만들기 상한, 운영자 역할, 조직 삭제를 정한다(OQ-26~OQ-28).
