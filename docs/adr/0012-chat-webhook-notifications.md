# ADR-0012. 외부 알림: Google Chat 웹훅, 계정 종류 구분

> 버전: v0.1.0\
> 수정일: 2026-11-04

- 상태: Accepted
- 영향: [product/overview.md](../product/overview.md) §5.2·§6.2·§7, [architecture/tenancy.md](../architecture/tenancy.md) §6.4, [architecture/security.md](../architecture/security.md) §13.6, [domain/rules.md](../domain/rules.md) §10.3·§10.4, [product/screens.md](../product/screens.md) D2·E3·E6

## 맥락

- reberu는 누구나 쓰는 서비스다. Google Workspace를 쓰는 단체와 개인 Google 계정만 쓰는 단체가 함께 있다.
- 알림을 reberu 밖 메신저(Google Chat)로도 받고 싶다는 요구가 있다. 참고한 기존 앱은 관리자가 팀 대화방과 팀원별 방의 웹훅 주소를 모아 등록해 알림을 보냈다.
- Google Chat 웹훅은 유료 Workspace 계정만 만들 수 있다. 개인 Google 계정은 만들 수 없고, Workspace 관리자가 웹훅을 막을 수도 있다.
- 사람에게 DM을 보내려면 Google Chat 앱(봇)을 Google Cloud에 등록하고, 여러 조직이 쓰려면 Google Workspace Marketplace에 게시하고, 각 조직의 Workspace 관리자가 앱을 허용해야 한다. 쓰려는 조직이 Workspace 관리자 권한을 갖고 있다고 기대할 수 없다.

## 결정

- 외부 알림은 팀 범위 모듈 "외부 알림"으로 둔다. 모듈 안에 알림 제공자를 꽂는 구조로 만들고, 첫 제공자는 Google Chat 웹훅이다.
- 보내는 곳은 두 가지다.
  - 팀 대화방: 팀 관리자가 팀이 쓰는 Chat 방의 웹훅 주소를 등록한다.
  - 개인 방: 그 사람만 있는 Chat 방의 웹훅 주소를 본인이 등록하거나, 팀 관리자가 대신 등록한다. 대신 등록하면 본인이 확인하기 전까지 개수와 링크만 보낸다.
- 외부로는 알림을 하나하나 보내지 않는다. 개인 방에는 근무일 아침의 **모닝 브리핑**만, 팀 대화방에는 팀 관리자가 켠 팀 알림(기본은 레벨업만)만 보낸다. 마감 임박·업무 배정 같은 개별 알림은 앱 안에만 둔다.
- 인증·만료일 안내는 알림이 아니라 팀을 열 때 뜨는 D-day 모달로 보여 준다.
- 계정 종류(Workspace 계정 / 개인 계정)는 로그인할 때 ID 토큰의 `hd` 값으로 판정한다. 개인 Chat 알림 설정은 Workspace 계정에게만 보인다. 계정 종류는 권한 판정에 쓰지 않는다.
- Google Chat 앱(봇)은 만들지 않는다. 후보 기능으로 보류한다.
- 웹훅 주소는 비밀값으로 다룬다(암호화 저장, 원문 반환 금지, 정해진 주소 형식만 허용, 발송 대기열).

## 검토한 대안

| 대안 | 버린 이유 |
| --- | --- |
| Google Chat 앱(봇)으로 개인 DM | Marketplace 게시와 심사, 조직마다 Workspace 관리자의 앱 허용이 필요하다. 관리자 권한이 없는 조직은 쓸 수 없다 |
| 사용자 권한(OAuth)으로 그 사람 이름으로 보내기 | 알림이 "내가 나에게 보낸 메시지"가 되고, 사용자 토큰을 오래 보관해야 해 보안 부담이 크다 |
| 조직을 Workspace 조직과 일반 조직으로 나누기 | 구조와 권한이 두 갈래가 된다. 기능 안내만 계정 종류로 나누면 충분하다 |
| 팀 대화방만 지원 | 기존 앱에서 쓰던 팀원별 알림을 대신할 방법이 없다 |
| 개별 알림을 모두 Chat으로 보냄 | 메시지가 너무 많아 중요한 것이 묻힌다. 기존 앱도 개인 방에는 아침 브리핑만 보냈다 |

## 결과

- 좋아지는 점: Google에 앱 등록이나 심사 없이 v0.3에 팀·개인 Chat 알림을 함께 제공한다. 개인 Google 계정만 쓰는 단체도 나머지 기능을 모두 쓴다. 이메일·다른 메신저는 같은 제공자 구조로 더한다.
- 감수하는 점: 사람마다 Chat 방을 만들고 웹훅 주소를 등록해야 한다. 웹훅 주소가 새면 그 방에 누구나 글을 쓸 수 있으므로 비밀값 관리가 필요하다. Workspace 관리자가 웹훅을 막은 조직은 이 기능을 쓸 수 없다.
- 후속 작업: 제공자 등록 계약을 `architecture/modules.md`(작성 예정)에 둔다. 발송 대기열의 저장 방식은 도메인 모델에서 정한다.
