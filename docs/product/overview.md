# 제품 정의

> 버전: v0.2.0\
> 수정일: 2026-11-05

reberu가 무엇을 만들고 무엇을 만들지 않는지, 기능을 어떻게 나누는지, 어떤 순서로 만드는지 정한다. 용어는 [README.md](../README.md) §4를 따른다.

## 1. 목적

- reberu는 **팀 업무·출석 관리 서비스**다. 회사, 동아리, 스터디 등 어떤 단체든 쓴다.
- 업무 관리 위에 두 계층을 얹는다.
  - **가상 공간**: 동료가 아바타로 모이는 3D 공간. 업무 툴의 분위기와 만남을 맡는다.
  - **성장 요소**: 출석·업무 완료·칭찬이 EXP와 레벨로 쌓인다.
- 누구나 Google 계정으로 로그인해 조직을 만든다. 한 단체가 저장소를 복사해 자기 서버에 띄울 수도 있다([ADR-0003](../adr/0003-multi-org.md)).
- 복사한 저장소는 버전 태그로 업스트림 업데이트를 받는다. 단체별 기능은 업스트림 파일을 고치지 않고 확장 모듈로 더한다([ADR-0002](../adr/0002-core-and-modules.md)).

## 2. 목표와 비목표

### 2.1 목표

| ID | 목표 | 수준 |
| --- | --- | --- |
| PRD-GOAL-01 | 공간 기능을 모두 꺼도 업무·프로젝트·할 일·리포트·출석을 쓸 수 있다 | 필수 |
| PRD-GOAL-02 | 조직과 팀의 데이터가 서로 완전히 격리된다 | 필수 |
| PRD-GOAL-03 | 모듈을 더하거나 빼도 고정 기능과 다른 모듈의 코드를 고치지 않는다 | 필수 |
| PRD-GOAL-04 | 단체마다 공개 범위와 가입 방법을 골라 쓴다 | 필수 |
| PRD-GOAL-05 | 보안 취약점을 0에 가깝게 만든다. 보안 규칙마다 자동 테스트가 있다([architecture/security.md](../architecture/security.md)) | 필수 |
| PRD-GOAL-06 | 쉬는 것과 함께 있는 것이 부담 없이 자연스럽다(힐링 존, 조직 공간) | 권장 |

### 2.2 비목표

| 비목표 | 이유 | 대신 |
| --- | --- | --- |
| 음성·화상 통화 직접 구현 | 품질·비용 대비 얻는 것이 적다. 확장 후보로만 둔다(§7) | 외부 회의 링크를 연다 |
| 비밀번호·이메일 코드 로그인 | 비밀번호 저장과 계정 복구가 공격면이 된다 | Google OIDC만 쓴다([ADR-0004](../adr/0004-google-oidc-only.md)) |
| 업무 평가·감시 도구 | 순위·지각 판정이 압박이 된다 | 지각을 판정하지 않는다. 순위는 끌 수 있는 모듈이다 |
| 실제 날씨 연동 | 외부 서비스 의존과 위치 정보가 필요하다 | 가상 날씨(OQ-22) |
| 메신저 대체 | 범위가 커진다 | 라운지 채팅은 가벼운 대화만 맡는다 |
| 특정 단체 전용 기능 | 업스트림이 특정 단체에 묶인다 | 확장 모듈로 복사한 저장소에서 만든다 |
| 프로젝트 비밀 정보 보관 | 암호화·열람 통제가 따로 필요하다 | OQ-12 |

## 3. 사용자와 역할

상세 권한은 [architecture/tenancy.md](../architecture/tenancy.md) §9를 따른다.

| 사람 | 멤버 종류 | 역할 | 하는 일 |
| --- | --- | --- | --- |
| 조직 관리자 | `MEMBER` | `orgAdmin` | 팀 만들기·보관, 공개 범위·가입 방법, 직무 유형, 허용 모듈, 시간대·휴일 달력, 조직 멤버십 정지 |
| 팀 관리자 | `MEMBER` | `TEAM_ADMIN` | 가입·초대, 팀원 관리, 팀 설정, 팀 기능, 팀의 모든 업무 수정 |
| 팀원 | `MEMBER` 또는 `GUEST` | `TEAM_MEMBER` | 자기 업무, 할 일, 리포트 공지 칸, 공간 |
| 읽기 전용 | `MEMBER` 또는 `GUEST` | `VIEWER` | 보기만 |
| 손님 | `GUEST` | `TEAM_MEMBER` 또는 `VIEWER` | 초대받은 팀 안에서만, 정해진 기간 동안 |
| 운영자 | 해당 없음 | `Operator` | 배포 전체에서 조직 정지만(OQ-26) |

- 한 계정은 여러 조직·여러 팀에 속한다. 멤버 종류는 조직마다, 역할은 팀마다 따로다.
- 손님은 관리자 역할을 가질 수 없다.

### 5.2 기본 제공 모듈

출처는 모두 `BUNDLED`다. "의존"은 켜려면 먼저 켜져 있어야 하는 모듈이다.

| 모듈 | 범위 | 기본 켜짐 | 의존 | 내용 |
| --- | --- | --- | --- | --- |
| 칭찬 | `TEAM` | 켜짐 | 없음 | 동료에게 칭찬과 EXP를 보낸다 |
| 공간 | `TEAM` | 켜짐 | 없음 | 일하다 쉬러 가는 팀 공간(로비, 내 자리, 라운지, 회의실)과 보행, 위치 실시간. 업무 기능은 두지 않는다([ADR-0015](../adr/0015-healing-only-spaces.md), OQ-11) |
| 힐링 존 | `TEAM` | 켜짐 | 공간 | 바닷가(B5), 산길(B12), 날씨 |
| 오늘의 퀘스트 | `TEAM` | 꺼짐 | 없음 | 서버가 주는 작은 목표 (OQ-01, OQ-02) |
| 명예의 전당 | `TEAM` | 꺼짐 | 없음 | 시즌 순위 (OQ-05) |
| 아침 요약 | `TEAM` | 켜짐 | 없음 | 첫 출근 때 마감 요약 카드(B1). 외부 알림 모듈이 켜졌으면 개인 Chat 방으로 모닝 브리핑도 보낸다 |
| 인증·만료일 관리 | `TEAM` | 꺼짐 | 없음 | 이름·만료일·담당자. 만료가 다가오면 팀을 열 때 D-day 모달로 안내한다 |
| 조직 공간 | `ORG` | 꺼짐 | 없음 | 광장(B9), 연회장(B10). 조직 전체가 모여 쉬고 어울리는 곳 |
| 외부 알림 | `TEAM` | 꺼짐 | 없음 | 알림을 reberu 밖 메신저로 보낸다. 첫 제공자는 Google Chat 웹훅. 팀 대화방에는 팀 알림(기본 레벨업), 개인 방에는 모닝 브리핑만 보낸다. 제공자는 확장 모듈로 더할 수 있다 ([ADR-0012](../adr/0012-chat-webhook-notifications.md)) |

- 기본 켜짐 값은 직무 유형이 정하고, 직무 유형에 없으면 이 표의 값을 쓴다(OQ-41).
- 공간을 끄면 힐링 존도 꺼진다. 공간을 다시 켜도 힐링 존은 따로 켠다(OQ-43).
- 회의실(B4)은 모여 앉는 방과 외부 회의 링크만 둔다. 안건·메모·결과 같은 회의 기록 기능은 두지 않는다([ADR-0015](../adr/0015-healing-only-spaces.md)).
- 모듈별 도입 단계는 §6.2를 따른다.

- 팀 범위 모듈은 조직 관리자가 허용(F4)해야 팀 관리자가 켤 수 있다(E6).
- 조직 범위 모듈은 조직 관리자가 켠다(F4). 팀 기능 화면에는 나오지 않는다.
- 모듈을 끄면 그 모듈의 메뉴·화면·API·알림·EXP 출처가 사라진다. 쌓인 기록은 지우지 않고, 다시 켜면 이어진다.

### 5.3 확장 모듈

- 확장 모듈(`EXTENSION`)은 복사한 저장소가 자기 패키지에 더한 모듈이다. 예: 특정 직무용 인증 관리, 단체 고유의 업무 구분.
- 확장 모듈은 기본 제공 모듈과 같은 확장 지점으로 등록한다. 업스트림 파일을 고치지 않는다([ADR-0002](../adr/0002-core-and-modules.md), CONTRIBUTING.md §3).
- 확장 모듈은 core의 보안 확인(지금 팀, 권한, 모듈 켜짐)을 우회할 수 없다([architecture/security.md](../architecture/security.md)).
