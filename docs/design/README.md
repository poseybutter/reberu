# reberu 설계 문서

> 상태: **초안**. 저충실도 와이어프레임 단계입니다. 이 문서로 다음 단계에서 도메인 모델과 API 목록을 뽑습니다.

## 목적

화면마다 **어떤 데이터가 보이고, 어떤 행동이 일어나고, 무엇이 실시간으로 바뀌는지**를 분명히 하는 것이 목적입니다. 시각 디자인(그림체, 색, 캐릭터)은 범위가 아닙니다.

## 서비스 한 줄 소개

출근하면 동료들이 한 공간에 아바타로 모여 있고, 티타임과 회의를 하고, 쉬고 싶으면 바닷가로 달려가는 **"가상 사무실 + 힐링"** 콘셉트의 팀 업무·출석 관리 서비스입니다. 업무 완료, 출석, 칭찬이 경험치(EXP)와 레벨로 쌓입니다.

## 화면 방향 (확정)

reberu는 **업무 관리 툴**이고, 가상 공간은 그 위에 얹은 분위기입니다. 둘이 부딪히면 언제나 업무 쪽을 고릅니다.

### 원칙

1. **업무는 공간을 거치지 않는다.** 업무, 퀘스트, 상태 바꾸기, 알림 같은 업무 행동은 어느 공간에 있든 업무 패널에서 바로 할 수 있습니다. 공간 이동은 분위기와 만남을 위한 선택이지 업무의 필수 경로가 아닙니다.
2. **업무 패널은 항상 같은 자리에 있다.** 화면은 "공간 뷰 + 업무 패널" 두 영역으로 나누고, 공간을 옮겨도 패널의 위치와 내용 구성은 바뀌지 않습니다.
3. **연출은 업무를 막지 않는다.** 레벨업, 업적, EXP 지급 같은 연출은 하던 일을 가리는 창으로 띄우지 않고, 짧은 알림으로 보여 준 뒤 눌렀을 때만 자세히 엽니다.
4. **조용한 것이 기본이다.** 카메라는 캐릭터 뒤에서 천천히 따라오고 크게 돌지 않습니다. 소리는 기본으로 꺼 둡니다. 깜빡이거나 흔들리는 효과는 쓰지 않습니다.
5. **언제든 공간 없이 쓸 수 있다.** 단순하게 보기(B7)에서도 같은 기능을 모두 쓸 수 있습니다. 공간에서만 되는 업무 기능은 만들지 않습니다.
6. **공간과 업무 화면은 다른 곳이다.** 공간(팀 공간 B1~B5, 조직 공간 B9~B11)은 걸어 다니며 만나고 쉬는 곳이고, 업무·프로젝트 관리는 공간이 아닌 평범한 화면입니다.

### 화면 종류

| 종류 | 화면 | 모습 |
| --- | --- | --- |
| 팀 공간 | 로비, 내 자리, 라운지, 회의실, 힐링 존(바닷가 B5, 산길 B12) (B1~B5, B12) | 걸어 다니는 3D 공간 + 업무 패널 |
| 조직 공간 | 광장, 연회장, 공용 회의실 (B9~B11) | 조직 전체가 함께 들어오는 3D 공간 + 업무 패널(지금 보는 팀) |
| 업무 화면 | 업무 목록·상세, 프로젝트, 퀘스트, 프로필, 리포트, 알림 (C, D) | 공간 없는 평범한 2D 화면 |
| 관리 화면 | 관리자 화면 (E) | 공간 없는 평범한 2D 화면 |

공간 화면의 배치:

| 영역 | 내용 |
| --- | --- |
| 공간 뷰 | 지금 있는 공간, 걸어 다니는 동료 아바타, 공간별 행동 막대 |
| 업무 패널 | 내 상태, 오늘 할 업무, 오늘의 퀘스트, 알림 바로가기. 어느 공간에서나 같은 자리에 고정. 자세히 보려면 업무 화면으로 엶 |

- 모바일은 업무 패널이 기본 화면이고, 공간 뷰는 탭으로 엽니다.

### 공간별 3D 세기

공간마다 업무와의 거리에 따라 연출의 세기를 다르게 합니다.

| 세기 | 공간 | 이유 |
| --- | --- | --- |
| 강 | 힐링 존(바닷가, 산길) | 쉬러 가는 곳이라 분위기가 곧 기능 |
| 중 | 로비, 티타임 라운지 | 만나고 인사하는 곳. 동료가 잘 보이는 정도 |
| 약 | 내 자리, 회의실 | 일하는 곳. 공간은 배경으로만 두고 업무 정보가 먼저 보임 |
| 없음 (2D) | 업무·관리 화면 | 업무 툴 화면 그대로 |

바닷가 요가원 같은 차분한 분위기를 목표로 하지만, 3D를 과하게 내세우지 않습니다.

### 이동 방식: 공간 사이는 고르고, 공간 안은 걷기

- **공간 사이**는 공간 목록 버튼이나 미니맵(B6)으로 골라서 바로 옮깁니다. 공간에서 공간으로 걸어갈 필요는 없습니다.
- **공간 안**은 걸어 다닙니다. PC는 WASD·방향키와 클릭 이동, 휴대폰은 화면 왼쪽 아래 조이스틱을 씁니다.
- 공간마다 경계가 있고, 큰 물체(테이블, 파라솔 등)는 통과하지 못합니다.
- 자리(매트, 의자, 책상) 가까이 가면 "앉기" 같은 행동 버튼이 뜹니다. 앉으면 아바타가 그 자리에 머뭅니다.
- 공간마다 정원이 있습니다. 정원이 차면 들어갈 수 없고, 이때도 업무 패널과 업무 화면은 그대로 쓸 수 있습니다.
- **업무 입력이 먼저입니다.** 업무 패널이나 채팅 입력 칸에 글을 쓰는 동안에는 이동 키가 먹지 않습니다. 이동 키는 공간 뷰를 누른 뒤에만 동작합니다.
- 서버는 같은 공간에 있는 사람끼리만 위치를 주고받습니다. 다른 공간에는 "누가 어느 공간에 있는지"만 알립니다. 보내는 빈도는 [05-realtime.md](05-realtime.md)에서 정합니다.

## 기능 구성 (확정)

reberu의 기능은 **고정 기능**과 팀마다 켜고 끄는 **기능 모듈**로 나눕니다. 조직 관리자가 조직에서 쓸 수 있는 모듈을 허용하고, 팀 관리자는 그 안에서 팀 기능 화면(E6)으로 켜고 끕니다. 팀을 만들 때 고르는 **직무 유형**이 켤 모듈과 항목의 기본값을 채웁니다([06-multi-team.md](06-multi-team.md)).

| 층 | 기능 | 어디에 |
| --- | --- | --- |
| 고정 (모든 팀 공통, 끌 수 없음) | 업무, 프로젝트, 오늘의 할 일, 리포트, 출석, EXP·레벨·시즌, 알림, 팀·역할·승인·활동 기록 | reberu |
| 기능 모듈 (팀마다 켜고 끔) | 공간(가상 사무실), 오늘의 퀘스트, 칭찬, 명예의 전당, 아침 요약, 인증·만료일 관리 | reberu |
| 조직 단위 모듈 (조직이 켜고 끔) | 조직 공간(광장, 연회장, 공용 회의실) | reberu |
| 조직 모듈 | 복사한 조직의 직무에 맞춘 모듈 (예: 웹 접근성 인증 관리, 조직 고유의 업무 구분) | 복사한 저장소 |

- 업무, 리포트, 시즌처럼 고정 기능의 규칙은 모든 팀이 같습니다. 팀마다 다른 것은 어떤 모듈을 켰는지와 팀 설정 값(정원, 리포트 마감 시각 등)뿐입니다.
- 모듈을 끄면 그 모듈의 메뉴, 화면, 알림, EXP 출처가 그 팀에서 사라집니다. 쌓인 기록은 지우지 않고, 다시 켜면 이어집니다.
- **조직 모듈은 reberu에 넣지 않습니다**([CONTRIBUTING.md 3절](../../CONTRIBUTING.md#3-업스트림-운영-규칙)). reberu는 모듈을 붙이는 확장 지점(모듈 등록, 메뉴, 권한, EXP 출처, 마이그레이션 위치)을 제공하고, 복사한 저장소는 업스트림 파일을 고치지 않고 자기 패키지에 모듈을 더합니다. 확장 지점의 코드 구조는 도메인 모델 단계에서 정합니다.
- reberu에 넣는 모듈은 여러 조직이 쓸 만한 일반 기능만 둡니다. 예를 들어 "인증·만료일 관리"는 이름, 만료일, 담당자, 미리 알림만 다루는 일반 모듈이고, 웹 접근성 인증처럼 특정 직무에 맞춘 단계·용어는 조직 모듈에서 이 모듈을 넓혀 만듭니다.

## 사용자와 역할

- **구성원**: 출근, 업무, 할 일, 퀘스트, 티타임, 회의, 휴식을 합니다. 업무는 자기가 담당자인 것만 고칩니다.
- **읽기 전용**: 보기만 합니다. 업무를 만들거나 고치지 못합니다.
- **팀 관리자**: 구성원 승인, 팀·역할·팀 기능 관리, 기록 확인을 합니다. 팀의 모든 업무를 고칠 수 있습니다.
- **조직 관리자**: 팀 만들기·보관, 직무 유형, 조직에서 허용할 모듈, 로그인 허용 기준, 계정 정지를 맡고, 모든 팀의 관리 화면을 봅니다.
- 배포 하나가 조직 하나이고, 조직 안에 팀이 여럿 있습니다. 한 사람이 여러 팀에 속할 수 있고, 기록은 팀마다 따로입니다. 위쪽 막대에서 **지금 보고 있는 팀**을 바꿉니다. 자세한 구조는 [06-multi-team.md](06-multi-team.md)입니다.

## 와이어프레임 표현 규칙

- 흑백·회색조만 씁니다. 강조는 굵기와 `▓`(진한 회색) / `░`(옅은 회색)로만 구분합니다.
- 공간은 위에서 내려다본 평면도로 그리고, 가구·소품은 이름이 적힌 상자로 표시합니다. 예: `[테이블]`, `[찻주전자]`, `[파라솔]`
- 이미지 자리는 `[X 무엇이 들어갈지]`로 표시합니다.
- 화면 글자는 한국어로, 짧고 친근하게 새로 씁니다. 예시 데이터는 모두 지어낸 값입니다.
- 한글 폭 때문에 오른쪽 테두리는 생략합니다.

### 범례

| 표시 | 뜻 |
| --- | --- |
| `(하늘)` | 아바타 (원 + 이름표) |
| `●` | 한가함 |
| `◐` | 집중 중 |
| `◆` | 회의 중 |
| `○` | 자리 비움 |
| `[X 라벨]` | 이미지 자리 |
| `⟶ B1` | 이 행동을 하면 B1 화면으로 이동 |
| ★ | 모바일(390×844) 화면도 그림 |

## 레퍼런스

아이디어와 방식은 모두 가져오고, 실제 결과물(그림 파일, 캐릭터, 맵 배치, 화면 문구, 로고, 서비스 이름)은 새로 만듭니다.

| 레퍼런스 | 가져온 아이디어 |
| --- | --- |
| 온라인 요가원 | 정원이 있는 공간 목록, 아바타로 모인 접속자, 아래쪽 행동 막대, "○○님이 인사했어요" 알림, 위쪽 시각·접속자 수 |
| 산사 | 방 단위 공간, 기다림·반복을 쌓이는 숫자로 보여 주는 연출 |
| Gather | 한가함·집중 중·회의 중 상태 표시, 손 흔들어 부르기, 내 상태 설정, 단순하게 보기, 미니 모드, 책상·아바타 꾸미기 |
| ZEP | 늘 열어 두는 사무실형 공간, 리액션, 채팅, 업무 외 놀이 요소 |
| 온라인 순례길 | 길을 걷는 공간(산길 B12), 인사·멈추기·앉기 같은 짧은 행동, 길 위에 말 남기기(돌탑), 구간 도장과 출석 도장판 |

온라인 순례길은 2026-11-04에 글자로만 읽었고 메뉴 이름(인사, 멈추기, 앉기, 말 남기기, 도장)과 "걷기 시작" 버튼만 확인했습니다. 실제 화면은 브라우저로 열어 확인해야 합니다.

그림체 후보(나중에 고름): 동글동글한 단순 3D, 2D 도트풍.

## 정하지 못한 점과 부딪히는 점

와이어프레임을 그리면서 나온 질문입니다. 도메인 모델을 뽑기 전에 정해야 합니다.

| # | 내용 | 초안의 가정 |
| --- | --- | --- |
| 1 | **(퀘스트 모듈 설계 때 정함) 오늘의 퀘스트는 누가 정하나.** 서버가 정해진 목록에서 뽑는지, 팀 관리자가 정하는지, 구성원이 직접 적는지 | 둘로 나눔. **오늘의 할 일**(고정)은 구성원이 직접 적고, **오늘의 퀘스트**(모듈)는 서버가 공통 목록에서 매일 3개를 뽑음 |
| 2 | **(퀘스트 모듈 설계 때 정함) 퀘스트 체크 방식.** "체크하면 EXP"인데, 직접 체크인지 행동하면 자동 체크인지. 직접 체크면 누구나 바로 체크할 수 있음 | 할 일은 직접 체크(EXP 작게, 하루 상한). 퀘스트는 행동으로 확인되는 것만 두고 자동 체크 |
| 3 | **내 자리와 업무 목록이 겹침.** 업무 패널이 어디서나 오늘 할 업무를 보여 주므로 B2 내 자리의 역할이 겹침 | 오늘 할 것 요약은 업무 패널, 전체는 C1. B2는 집중하러 가는 공간(집중 시작, 책상 꾸미기) |
| 4 | **힐링 존에 있을 때 상태.** 상태가 네 가지(한가함, 집중 중, 회의 중, 자리 비움)뿐이라 휴식 중을 표시할 수 없음 | 힐링 존에 있으면 "한가함"으로 표시하고, 위치로 휴식 중임을 알 수 있게 함 |
